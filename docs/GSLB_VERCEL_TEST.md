# EC2 and Vercel HTTP failover test

The disposable endpoint at `/api/gslb-test` checks the configured EC2 Apache origin. On a successful bounded GET, it returns `{ "source": "ec2", "healthy": true }` without forwarding the origin response body. This avoids exposing EC2 private hostnames or other backend details. On timeout, network error, invalid origin, non-2xx status, or an oversized response, it returns a small fallback response generated by the Vercel Function.

## Vercel configuration

Set `GSLB_EC2_ORIGIN` to the EC2 HTTP origin in the Vercel project environment. It defaults to the supplied Mumbai test instance at `http://15.252.99.51`. Set it only for Preview until the test is complete. The function accepts GET only, does not accept a client-supplied destination, disables redirects and caching, and bounds timeout and response size.

## Test

Open `https://my-website-one-zeta-56.vercel.app/api/gslb-test`. With EC2 reachable, JSON reports `source: ec2`. Temporarily stop Apache on EC2 and repeat the same GET. It should return `source: vercel`. Restart Apache and verify the EC2 response returns.

This measures HTTP GET fallback through Vercel Functions. It does not test authoritative DNS, arbitrary application traffic, write requests, client sessions, GatewayCore production deployment, or a 99.9% availability window. EC2 traffic currently uses plain HTTP for this disposable test and must not carry secrets or user data.
